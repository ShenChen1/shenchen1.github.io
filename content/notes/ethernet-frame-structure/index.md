## 1. 为什么引入 802.1Q (单 Tag)？

### 解决的历史问题：单一物理网络下的广播风暴与业务隔离

早期的标准 Ethernet II 帧是一个完全平坦的二层网络，所有接入同一物理交换机或同轴电缆的主机属于同一个广播域。随着局域网规模扩大，暴露出两个核心问题：
- **广播风暴与泛洪**：ARP 广播、未知单播泛洪占用整网带宽，终端 CPU 频繁处理无关中断。
- **缺乏安全隔离**：不同部门、敏感服务器与普通办公终端共用二层，无法在链路层做权限划分。

### 怎么塞进现有以太网？

为了在不破坏原有以太网物理接收逻辑的前提下携带隔离标识，IEEE 802.1Q 采用**在源 MAC（SMAC）与以太网类型（EtherType）之间“插队”插入 4 个字节 Tag** 的方式：
- **TPID (`0x8100`)**：占据原本 EtherType 的位置。老旧不支持 VLAN 的交换机会将其视为未知协议直接丢弃或透传；支持 802.1Q 的设备则识别出后续内容为 VLAN 标签。
- **12-bit VID (VLAN ID)**：理论支持 4096 个 VLAN（保留 0 和 4095，可用 4094 个），让单一物理交换网络可以划分为 4094 个逻辑广播域。
- **3-bit PCP**：顺带补充了以太网原本缺乏的 QoS 服务质量分级（0~7），供语音、视频流量在拥塞时优先排队。

## 2. 为什么进一步引入 802.1ad (QinQ 双 Tag)？

### 解决的历史问题：城域网 4096 上限与租户 VLAN 规划冲突

当运营商开始用以太网构建城域网（Metro Ethernet）、为企业提供二层专线时，单层 802.1Q 暴露出致命的瓶颈：

1. **4094 个 VLAN 严重不够用**：一个城域网要接入成千上万家企业，全网共享 4094 个 ID 迅速枯竭。
2. **租户 VLAN 规划与运营商网络强耦合**：企业 A 在自己内网使用了 VLAN 100~200，企业 B 在内网也使用了 VLAN 100~200。如果运营商直接使用 802.1Q，不同企业的数据在骨干网必然串扰；而强制要求所有客户配合运营商统一分配规划私网 VLAN 在商业上根本不可行。

### 解决方式：802.1Q-in-802.1Q (QinQ)

802.1ad 的核心思想是**二层轻量级隧道封装**：在用户带 Tag 的报文（Customer Tag，C-Tag）外面，由运营商边缘设备（PE）再打上一层服务商 Tag（Service Tag，S-Tag）：

```text
[DMAC] [SMAC] + [S-Tag (外层: 运营商分配)] + [C-Tag (内层: 用户私有)] + [EtherType] + [Payload] + [FCS]
```

- **黑盒透传**：运营商骨干网仅依据外层 S-Tag 进行路由和隔离，对内层 C-Tag 完全透明。用户内网即使使用相同的 VLAN ID 也互不干扰。
- **容量扩容**：将 VLAN 理论容量从 $4096$ 扩展至 $4096 \times 4096$（约 1600 万）。

## 3. 演进带来的工程代价与常见踩坑

引入两层 Tag 在网络工程中带来了两个非常隐蔽的经典问题：

### MTU 黑洞（Giant Frame 丢弃）
- 标准 Ethernet II 帧的最大传输单元（MTU）是 1500 字节，整帧最大长度为 `1518` 字节（14B Header + 1500B MTU + 4B FCS）。
- 单层 802.1Q 使整帧膨胀到 `1522` 字节，双层 QinQ 进一步膨胀到 `1526` 字节。
- **典型故障表现**：两端主机仍然按默认 1500 MTU 进行通信与 TCP MSS 协商，Ping 小包正常、TCP 三次握手成功；但在大流量传输时，携带有 1500 字节 Payload 的 QinQ 帧总长达到 1526 字节，超出中间未调大端口 MRU 的物理交换机上限，导致**大包被交换机直接静默丢弃（Silent Drop）**，TCP 连接陷入反复重传甚至挂死。
- **解决方法**：运营商及专线接入的 Trunk 端口必须将 MTU/MRU 调大至 `1526` 字节以上（通常直接开启 Jumbo Frame 设为 9000 或 9216）。

### 历史私有 TPID 兼容性问题
- IEEE 在 2005 年才正式将 802.1ad 的外层 TPID 标准化为 `0x88A8`。
- 在标准化之前，各主流厂商（如 Cisco、Huawei）早已有各自的私有 QinQ 实现，外层普遍使用 `0x9100` 或 `0x9200`。
- **典型故障表现**：跨厂商或新老设备级联对接 QinQ 时，若一侧为 `0x88A8`，另一侧默认认 `0x9100`，对端会将外层 Tag 识别为未知以太网类型，解封装失败导致网络不通。必须在端口上手动统一配置 `qinq-tpid`。
