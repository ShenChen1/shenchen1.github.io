## 编译

使用 `-g` 编译产生 debug symbols。`-g` 不会影响任何优化选项，debug symbols 可以在任何 `-O` 等级下生成。其他选项是为了强调使用 DWARF，显式关闭 unwind 方式：

```bash
$ arm-cortexa9_neon-linux-gnueabihf-gcc -g -o demo \
    -fomit-frame-pointer -fno-unwind-tables -fno-asynchronous-unwind-tables demo.c
```

编译完成后，可以用 `readelf` 观察 `.debug_*` section 是否生成：

```text
$ arm-cortexa9_neon-linux-gnueabihf-readelf -S demo
There are 35 section headers, starting at offset 0xc68:

Section Headers:
  [Nr] Name              Type            Addr     Off    Size   ES Flg Lk Inf Al
......
  [26] .debug_aranges    PROGBITS        00000000 000737 000020 00      0   0  1
  [27] .debug_info       PROGBITS        00000000 000757 000134 00      0   0  1
  [28] .debug_abbrev     PROGBITS        00000000 00088b 0000a8 00      0   0  1
```

## 分离调试信息

实际产品不会附带 debug symbols，所以这里把它们 strip 掉，单独保存为 [`.dbg`](demo.dbg) 文件：

```bash
# 提取调试信息
$ arm-cortexa9_neon-linux-gnueabihf-objcopy --only-keep-debug demo demo.dbg

# 从 binary 中去除调试信息
$ arm-cortexa9_neon-linux-gnueabihf-objcopy --strip-debug demo

# 在 binary 中添加 debug link，指向分离的调试文件
$ arm-cortexa9_neon-linux-gnueabihf-objcopy --add-gnu-debuglink=demo.dbg demo
```

执行完成后，binary 文件尺寸明显变小（最终二进制见 [`demo`](demo)）：

```text
# strip 前
-rwxr-xr-x 1 root root 6.9K May  9 17:19 demo

# strip 后
-rwxr-xr-x 1 root root 5.5K May  9 17:29 demo
```

同时可以看到新增了 `.gnu_debuglink` section，用来关联被分离的调试信息文件：

```text
$ arm-cortexa9_neon-linux-gnueabihf-objdump -s -j .gnu_debuglink demo

demo:     file format elf32-littlearm

Contents of section .gnu_debuglink:
 0000 64656d6f 2e646267 00000000 ad5f0c4c  demo.dbg....._.L
```

关于 `gnu_debuglink` 的详细说明：<https://sourceware.org/gdb/onlinedocs/gdb/Separate-Debug-Files.html>

## 配置目标环境

首先要让目标环境能够生成 coredump，并确保 coredump 文件生成在运行 binary 的当前目录：

```bash
$ ulimit -c unlimited
$ echo core > /proc/sys/kernel/core_pattern
```

## 触发段错误

```text
$ ./demo
Segmentation fault (core dumped)
$ ls core*
core
```

## GDB 调试

加载 binary 和 coredump，查看 backtrace：

```text
$ arm-cortexa9_neon-linux-gnueabihf-gdb
GNU gdb (crosstool-NG crosstool-ng-1.22.0) 7.10
......
(gdb) file demo
Reading symbols from demo...Reading symbols from /opt/share/note/how-to-debug-coredump/demo.dbg...done.
done.
(gdb) core core
warning: exec file is newer than core file.
[New LWP 768]
warning: Could not load shared library symbols for linux-vdso.so.1.
Do you need "set solib-search-path" or "set sysroot"?
Core was generated by `./demo'.
Program terminated with signal SIGSEGV, Segmentation fault.
#0  0x00008404 in myabs (a=0xbea2d000) at demo.c:5
5		if (*a < 0)
(gdb) bt
#0  0x00008404 in myabs (a=0xbea2d000) at demo.c:5
#1  0x00008470 in sum_abs (a=0xbea2ccd0, n=1000000) at demo.c:15
#2  0x000084e8 in main () at demo.c:24
```

GDB 成功定位到了段错误发生在 `demo.c:5` 的 `myabs` 函数中，并且显示了完整的调用栈。

### 加载动态库

还需要加载目标环境的动态库，使用 `set sysroot` 指向 rootfs：

```text
(gdb) set sysroot /opt/development/qemu-project/rootfs
Reading symbols from /opt/development/qemu-project/rootfs/lib/libc.so.6...done.
Reading symbols from /opt/development/qemu-project/rootfs/lib/ld-linux-armhf.so.3...done.
(gdb) info sharedlibrary
From        To          Syms Read   Shared Object Library
                        No          linux-vdso.so.1
0xb6e5de00  0xb6f4e6a0  Yes         /opt/development/qemu-project/rootfs/lib/libc.so.6
0xb6f7c800  0xb6f97d00  Yes         /opt/development/qemu-project/rootfs/lib/ld-linux-armhf.so.3
(*): Shared library is missing debugging information.
```

这里的动态库没有将 debug symbols 与 shared library 分离。如果分离了的话，还需要用 `set debug-file-directory` 加载调试信息文件。
